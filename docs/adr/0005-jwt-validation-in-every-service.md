# ADR-0005. JWT проверяется в Gateway и в каждом сервисе

**Статус:** принято

## Решение

- Booking Service выпускает JWT HS256 (`JwtTokenService`) со сроком 1 час и claims `uid`, `roles`.
- Общий модуль `common` настраивает каждый сервлетный сервис как Resource Server
  (`SecurityConfig`: `NimbusJwtDecoder`, роли из claim `roles` с префиксом `ROLE_`), включает
  `@EnableMethodSecurity` и единые JSON-ответы 401/403.
- Gateway тоже проверяет токен (reactive Resource Server), чтобы отсекать неаутентифицированные запросы
  до маршрутизации, и передаёт заголовок `Authorization` дальше без изменений.
- Межсервисные вызовы используют отдельный короткоживущий токен роли `INTERNAL`.

## Альтернативы

Асимметричные ключи (RS256 + JWKS) уменьшили бы распространение секрета, но потребовали бы
отдельного сервера авторизации — избыточно для учебного проекта. Переход возможен заменой
`JwtDecoder`/`JwtEncoder` без изменения контроллеров.
